# MoHAA Reloaded: native Vulkan

**MoHAA Reloaded** brings [OpenMoHAA](https://github.com/openmoh/openmohaa) natively to modern hardware. This is its `vulkan` branch: OpenMoHAA with a Vulkan renderer of its own, for 64-bit Linux and Windows. It plays Medal of Honor: Allied Assault, Spearhead and Breakthrough with your retail game data, on existing MOHAA and OpenMoHAA servers.

| Branch | Renderer | Status |
|---|---|---|
| `metal` | Metal, macOS on Apple Silicon | [Released](https://github.com/fortemoh/MoHAA-Reloaded/releases) |
| **`vulkan`** (this one) | Vulkan, Linux and Windows | [Released](https://github.com/fortemoh/MoHAA-Reloaded/releases/tag/v1.0.0) |

> [!IMPORTANT]
> **This is a fork, not the upstream project.** Problems with this port belong on [this repository's tracker](https://github.com/fortemoh/MoHAA-Reloaded/issues) (say which branch: `metal` or `vulkan`), not upstream's tracker or Discord.

- **Vulkan, drawn its own way.** `renderer_vulkan` starts from upstream's GL1 renderer with every OpenGL call replaced, then redesigned: the world and the static models are uploaded once per map and drawn from GPU memory, soldiers are skinned and lit in the vertex shader, dynamic lights are per pixel, and a map's pipelines are built while it loads, so nothing stalls the first time it is drawn. Vulkan is loaded at run time, and no OpenGL is left: upstream's GL1 and GL2 renderers are gone from the code, the build and the downloads.
- **Low input latency.** Frames are drawn straight into the swapchain image, with at most two frames in flight and nothing drawn from older input: from reading the input to the present takes 0.47 and 0.83 ms (medians) in two real matches at 1920x1080 uncapped, against 0.66 and 1.31 with upstream's GL1 renderer.
- **Movement apart from the frame rate.** The commands the server runs come from their own clock (`cl_movefps`, below), each exactly as long at any frame rate, and the view turns with every frame.
- **Smooth matches.** What used to load in the middle of a match (models announced late, a sound's first play, the soundtrack at a round restart) now happens while the map loads.
- **Fast.** In two real matches played back at 1920x1080 on an AMD Radeon 780M (an integrated GPU), the renderer's CPU time per frame is about half of upstream's GL1 renderer's (0.35 ms against 0.65, 0.68 against 1.26), frames take 35 to 40 % less time, and the 99th percentile is 1.2 ms against 1.9 and 1.4 against 2.4.
- **The Omaha sound mixer** (JayRewd's) instead of OpenAL: miniaudio for the device, gains per kind of sound, ducking, sounds behind walls muffled, and HRTF for headphones.
- **Same game online.** The network protocol, the server-side game code and the data formats are upstream's, except that backpedal and strafe move at the original game's speeds, and a server it hosts caps SMGs and rifles at the original's top speeds and readies guns to fire on the original's frames.

Needs a GPU with a Vulkan 1.1 driver (on Linux Mesa's RADV, ANV or NVK, or NVIDIA's driver; on Windows any current AMD, NVIDIA or Intel driver). The Linux build needs glibc 2.34 or later (Ubuntu 22.04, Debian 12, Fedora 35 or later), the Windows build the [Microsoft Visual C++ 2015–2022 Redistributable (x64)](https://aka.ms/vs/17/release/vc_redist.x64.exe), which most PCs with games already have; SDL 3 comes with both (the Linux build uses the SDL 3 next to it, so distributions without one, like Ubuntu 22.04 and 24.04, need nothing). On a Wayland desktop the game is a native Wayland client (`SDL_VIDEODRIVER=x11` runs it under Xwayland). Developed and measured on an AMD Radeon 780M with Mesa's RADV driver under KDE Plasma (Wayland); also played on an NVIDIA RTX 4070 Ti.

## Install

1. Download `mohreloaded-1.0.0-linux-amd64.tar.gz` (64-bit Linux) or `mohreloaded-1.0.0-windows-x64.zip` (64-bit Windows) from [Releases](https://github.com/fortemoh/MoHAA-Reloaded/releases/tag/v1.0.0) and extract it (`tar xf mohreloaded-1.0.0-linux-amd64.tar.gz`; on Windows, right-click and Extract All).
2. Find your MOHAA game folder: the folder with `main/` (`Pak0.pk3` to `Pak6.pk3`; `mainta/` and `maintt/` for the expansions). Upstream's [installation guide](docs/markdown/01-intro/01-installation.md#linux-and-macos-users) shows how to get it from the GOG installer.
3. Copy everything in the extracted folder into the game folder, next to `main/` (its own `main/` only holds the headphone sound set: let it merge), and start `mohlauncher` (`mohlauncher.exe` on Windows): [MoHAA Launcher](#mohaa-launcher). `mohreloaded` (`mohreloaded.exe` on Windows) starts the game directly too: Allied Assault, or Spearhead with `+set com_target_game 1` and Breakthrough with `+set com_target_game 2`.

On Linux you can also leave the game folder as it is and start the game from the extracted folder: `./mohreloaded +set fs_basepath /path/to/mohaa`. `INSTALL.txt` in the download has the same steps. Started from MoHAA Launcher, the game keeps everything in the game folder (below). Started otherwise, configs go to `~/.config/openmohaa/` and saves and screenshots to `~/.local/share/openmohaa/` on Linux, all of them to `%APPDATA%\openmohaa\` on Windows, as with upstream's OpenMoHAA. Without a Vulkan driver the game stops and says so.

Downloads before the rename were called `openmohaa-vulkan-1.0.0-…`, with the game as `openmohaa`: their launcher doesn't see the new downloads, so download this one by hand once and copy it over the old one (you can delete the old `openmohaa` program). Your settings stay where they were.

### MoHAA Launcher

`mohlauncher` (`mohlauncher.exe` on Windows) starts the game for Allied Assault, Spearhead or Breakthrough, at its main menu (**Single player**) or onto a server (**Connect**):

- **Servers:** the address, the server's password and the RCON password. **Bookmark** keeps a server in the list, with its passwords (joining one doesn't), four at most with Forte FFA built into Allied Assault's, so it never scrolls: remove one to make room.
- **Settings:** your name, **Discord presence** beside it (what you play on your Discord profile while Discord runs, `cl_discordPresence`, off unless you turn it on), and beside the server list the resolution and the display mode. Only what you change in the launcher goes to the game, so what you change in the game stays. The crosshair is set in the game (Options' HUD tab, or `crosshair_import` with a CS2 code).
- **Updates:** at each start it asks GitHub whether [the release](https://github.com/fortemoh/MoHAA-Reloaded/releases/latest) has a newer build than the game beside it (by the commit in the game's version). If so, it offers to update: **Update** downloads it, checks its SHA-256, and puts the files that changed in place of the old ones, putting the old ones back if one can't be replaced; your settings, configs and saves aren't in the download, so they stay. It waits while the game is running, and starts again if the update replaced it. A build of your own (a commit GitHub doesn't have, or one with changes the release lacks) is never offered one.
- **Portable:** it writes only into the game folder. `mohlauncher.json` holds the servers and their passwords; the game is started with its home there (`fs_homepath`), so its configs, saves, screenshots, demos and logs go there too. A config an earlier start kept in `~/.config/openmohaa/` or `%APPDATA%\openmohaa\` is copied over once.
- It finds the game folder by its `main/Pak0.pk3`, beside it or in the current folder, and asks for it otherwise. It needs nothing installed (on Linux, fontconfig and X11 or Wayland, as any desktop has).

Its source is [`launcher/desktop`](launcher/desktop) (Rust and Slint: `cargo build --release` there); CI builds it with the game.

Builds of newer commits come from [CI on this branch](https://github.com/fortemoh/MoHAA-Reloaded/actions/workflows/branches-build.yml?query=branch%3Avulkan) (`out-linux-amd64`, `out-windows-x64`; needs a GitHub login, kept for a few days), or build it yourself (below).

## Settings that matter here

Low input-to-screen time with even frames, as played on a 240 Hz display (tearing allowed):

```
seta com_maxfps 250
seta r_fullscreen 1
```

Change settings in the console (`seta name value`) or at launch (`+set name value`). Latched settings take effect after `vid_restart` (sound settings after `snd_restart`). Both ports' settings side by side: [the settings guide](https://github.com/fortemoh/MoHAA-Reloaded#settings-guide).

## Online

- The server side is upstream's: this client plays on stock MOHAA and OpenMoHAA servers.
- Backpedal and strafe move at the original game's speeds (upstream OpenMoHAA's are 25% and 18% faster), in this client's prediction and on a server it hosts. Your movement then matches stock MOHAA servers and servers with the same fix ([openmohaa-server](https://github.com/fortemoh/openmohaa-server)); on an upstream OpenMoHAA server, the server corrects you slightly while you backpedal or strafe, until upstream changes too.
- A player's top speed is truncated as MOHAA 1.11 does it, on a server this build hosts: at the default `sv_dmspeedmult 1.1` an SMG runs at 262 (upstream OpenMoHAA: 264) and a rifle at 257 (258); other weapons are unchanged. It isn't a setting. On other servers your speed is theirs.
- Fire delays are rounded as MOHAA 1.11 does it, on a server this build hosts: a gun whose delay is a whole number of server frames is ready on the earlier frame as often as in stock (at `sv_fps 20` the Garand about 54% of shots, upstream OpenMoHAA 20%), and in Allied Assault a pistol whip right after a shot waits the 0.1 s delay, as in stock. It isn't a setting. On other servers the timing is theirs.
- A server receives `cl_movefps` commands a second (100 by default), each exactly one step long, as from a stock client at that frame rate (at `cl_movefps 0`, one per frame). A shot or a jump in the first half of a step splits that step in two (`cl_movesubgrid`: 5 + 5 ms at 100, the steps of a stock client at 200 frames a second), one more command and packet for it.

## Building

Linux needs CMake 3.25 or later, Ninja, Clang or GCC, Flex, Bison, SDL 3 (3.2.0 or later; the downloads and CI use 3.4.18) and the Vulkan headers 1.4 (Khronos' Vulkan-Headers; distributions' packages may be too old: Ubuntu 22.04's are):

```bash
sudo apt-get install -y cmake ninja-build clang lld flex bison
```

SDL 3 is `libsdl3-dev` on Ubuntu 25.04 and later and Debian 13 (`SDL3-devel` on Fedora). Ubuntu 22.04 and 24.04 have none: build SDL 3.4.18 as CI does, with the X11 and Wayland development files (without them SDL can't open a window):

```bash
sudo apt-get install -y libx11-dev libxext-dev libxrandr-dev libxcursor-dev libxfixes-dev libxi-dev libxss-dev libxtst-dev libxkbcommon-dev libwayland-dev libdecor-0-dev libegl1-mesa-dev libdrm-dev libgbm-dev libudev-dev libpulse-dev libasound2-dev
git clone --depth 1 -b release-3.4.18 https://github.com/libsdl-org/SDL.git
cmake -S SDL -B SDL/build -G Ninja -DCMAKE_BUILD_TYPE=Release -DSDL_TESTS=OFF -DCMAKE_INSTALL_PREFIX="$PWD/sdl3"
cmake --build SDL/build && cmake --install SDL/build
```

and add `-DSDL3_DIR="$PWD/sdl3/lib/cmake/SDL3"` to the configure line below.

```bash
git clone --depth 1 -b v1.4.341 https://github.com/KhronosGroup/Vulkan-Headers.git
cmake -S Vulkan-Headers -B Vulkan-Headers/build -DCMAKE_INSTALL_PREFIX="$PWD/vulkan-headers"
cmake --install Vulkan-Headers/build
```

```bash
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release -DVulkanHeaders_DIR="$PWD/vulkan-headers/share/cmake/VulkanHeaders"
cmake --build build
```

Run it from `build/Release` with your game data: `./mohreloaded +set fs_basepath /path/to/mohaa`, or install it into the game folder (`-DCMAKE_INSTALL_PREFIX=/path/to/mohaa`, then `cmake --install build`; the installed game looks for `libSDL3.so.0` in its own folder first, so with an SDL 3 built as above copy it there: `cp -L sdl3/lib/libSDL3.so.0 /path/to/mohaa/`). `glslc` is only needed to change the shaders, the Vulkan validation layers only for `r_vkValidation`. CI builds Linux and Windows on every push (`.github/workflows/branches-build.yml`). The version is set in `cmake/identity.cmake` (1.0.0); a build says `1.0.0-unstable+<CI run>.<commit>`. Pushing a version tag (`v1.0.1`, once the code says 1.0.1) builds a release without "unstable" and makes a draft of it on GitHub (`.github/workflows/tags-publish-release.yml`), to be published by hand. This branch has no macOS build (the `metal` branch is the macOS port).

## Looks and limits

- **Looks like upstream's GL1 renderer**, except where a change bought speed: dynamic lights per pixel (a smoother falloff than GL1's lightmap texels), up to 64 of them and on doors and lifts too, and a few pixels where the drivers rasterize differently.
- **Measured on Linux**, on AMD (Mesa) and NVIDIA. Reports are welcome. On macOS, play the `metal` branch.
